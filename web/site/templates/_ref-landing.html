A smart lock that measures distance instead of trusting it.

UltraWideLock is firmware and a protocol stack for UWB secure ranging, BLE and NFC. Time-of-flight measurement under a rotating STS session, so an approach unlock cannot be relayed from across the street. Runs on nRF5340, DWM3001CDK and ESP32.

Install

Clone, pull the toolchain, build for a board. Nothing phones home.

shellwest workspace
# toolchain: Zephyr 3.7 + nRF Connect SDK, or ESP-IDF 5.2 for the ESP32 target
git clone https://git.ultrawidelock.com/ultrawidelock/ultrawidelock.git
cd ultrawidelock && west init -l . && west update

# build and flash the reference lock on nRF5340
west build -b nrf5340dk/nrf5340/cpuapp apps/lock
west flash

No merged image on hand? The web flasher writes a prebuilt ESP32-S3 bundle over WebSerial from the browser.

Three radios, one credential

  • UWB secure ranging DS-TWR under an STS session keyed per unlock. Range integrity checks reject relayed and replayed frames before the lock ever moves.
  • BLE transport Discovery, session setup and DFU over a single GATT service. The UWB session only opens once BLE has proved the credential.
  • NFC fallback Tap-to-unlock over ISO 14443-4 with the same access document, for a dead phone battery or a card credential.

Security model

Every unlock is two independent proofs: a signed access document presented over BLE or NFC, and a physical distance bound measured by UWB. Neither alone opens the bolt.

note

Keys live in the SoC's key store (CryptoCell on nRF, HMAC-eFuse on ESP32) and never leave it. The access document is verified on-device; there is no cloud verifier to compromise.

  • STS rotationper-session keys derived from the BLE handshake
  • range integrityCIR and RSSI gates against relay attacks
  • signed DFUEd25519 image verification before applying
  • flight recorderring buffer of every ranging decision, readable over BLE
