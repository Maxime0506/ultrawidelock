# Files semgrep's parser cannot read, and therefore does not scan.
#
# This is a coverage ledger, not a suppression list. Semgrep reports a parse failure as an error
# and still exits 0, so without this file a source file could stop being scanned — by acquiring a
# macro form the parser chokes on — and every run would keep reporting success. That is the
# failure mode this repository already guards against everywhere else: `scripts/verify.sh` fails
# when a gate's tool is missing, `tests/tooling/verify_test.sh` fails when a CI job has no local
# gate. Same rule here.
#
# The `semgrep` gate in scripts/security.sh fails if a file not listed here fails to parse.
# Removing a line is always safe; adding one is a deliberate widening of a known blind spot and
# should say why in the pull request.
#
# Why these fail: semgrep parses C without a preprocessor, so it stops on the macro-heavy forms
# these files use — Zephyr's K_TIMER_DEFINE and LOG_MODULE_REGISTER, the SHELL_* command tables,
# ESP-IDF driver config initialisers. twin_glue.c is the shim for the generated Emscripten
# output.
#
# web-twin/twin.js is NOT here, though it used to be. It is excluded in .semgrepignore, so it
# is never scanned and can never report a parse error — the entry sat here claiming a
# coverage gap that a different file already accounted for, and the gate now warns when a
# baselined path parses fine, which is how it was found.
#
# What actually covers this code, since semgrep does not:
#
#   clang-tidy   compiles it for real, with the include paths and defines, under bugprone-*,
#                cert-* and clang-analyzer-* with warnings as errors (clang-tidy.yml)
#   CodeQL       builds a database from `make test` and runs security-extended, which is the
#                deeper C dataflow analysis (security-deep.yml, weekly)
#   CBMC         proves memory safety on the wire parsers for all inputs up to each bound
#   libFuzzer    exercises the parsers with ASan and UBSan
#
# So the blind spot is narrower than the list looks: it is semgrep's pattern rules only, over
# files that four other gates do read.

# Bisected, for whoever tries to fix these rather than baseline them:
# dfu_ble_zephyr.c:235, status_led.c:41, dfu_receiver.c:81 and :85. It is not the Zephyr
# macro that breaks the parse. Any `static SOME_MACRO(a, b);` at file scope does, because
# without a preprocessor that reads as a storage class on a call expression. Dropping
# `static` parses, and is refused here: it turns internal linkage into external across the
# whole DFU surface, which is a worse defect than the blind spot it buys.
#
# modules/woz_dfu below is LOG_MODULE_REGISTER plus the two
# `static K_WORK_DELAYABLE_DEFINE(...)` in dfu_receiver.c, the same cause.
#
# modules/woz_dfu/src/dfu_smp_img.c was in this batch and is deliberately NOT listed. Its
# cause was a different one -- an #ifdef between designated initializers -- which was
# fixable without touching semantics, so it was fixed instead: the .mg_group_name
# assignment moved into woz_smp_img_init(). That file parses SMP upload frames off the
# air, so it is the one that most wanted the rules run against it. Do not re-add it
# without first confirming it actually fails to parse.
#
# Read this before trusting the compensating-controls list at the top of this file: it does not
# hold for these. modules/woz_dfu is in none of the fallbacks.
#
#   clang-tidy   compiles UNIT_SRCS out of tests/host/sources.sh (scripts/verify.sh:415), and
#                that file does not mention dfu anywhere
#   CBMC, fuzz   no harness under tests/host/cbmc or tests/host/fuzz references it
#   host suite   tests/host/run.sh:23 builds only the sources.sh arrays. A dfu suite is being
#                written -- tests/host/test_dfu.c and tests/host/dfufake/ -- but both are still
#                untracked and neither is named in sources.sh, so nothing compiles them yet.
#                When that lands, this row stops being a gap and this entry should be revisited
#   CodeQL       the header says it builds from `make test`, which is that same run.sh; if that
#                is still true the gap applies there too. Not settleable from this tree, since
#                security-deep.yml:16 says CodeQL runs under GitHub's default setup, configured
#                in the repository settings.
