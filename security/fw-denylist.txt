# security/fw-denylist.txt — byte patterns that must never appear in a shipped image.
#
# Format: <label> = <hex>, one per line, minimum 8 bytes. Comments after '#'.
#
# These are BYTE patterns, not strings, because that is what key material is. A 32-byte URSK that
# escaped a test fixture into a production build produces nothing in `strings` output and never
# will; the only way to find it is to look for the bytes.
#
# The entries below are the CCC test vector and everything the ladder derives from it, computed
# with the repository's own KDF. Regenerate after any change to ccc_kdf.c:
#
#   cc -std=c11 $DEFS $INCS tools/derive-testvectors.c \
#      modules/woz_uwb/src/ccc/ccc_kdf.c modules/woz_uwb/src/ccc/ccc_mac.c \
#      tests/host/aes_ref.c $SHIM_SRCS -o /tmp/derive && /tmp/derive
#
# The derived values are the ones that matter. They are high-entropy, so a hit is a hit — whereas
# the raw test URSK is a counting sequence (00 01 02 ... 1f) that can legitimately appear in a
# generated permutation or jump table, which is why it carries the caveat below rather than
# sitting here unqualified.
