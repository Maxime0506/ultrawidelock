# security/web-baseline.txt — paths knowingly failing scripts/security-web.sh, with the reason.
#
# A baselined path still PRINTS on every run, it just does not block. That is the difference
# between this file and a suppression list: the debt stays in front of whoever runs the gate
# instead of being deleted from the output. An entry that stops matching anything fails the gate,
# so a line cannot outlive the problem it describes.
#
# Lines are "<check>:<path>" (pins | csp | retire) or a bare "<path>" for every check.
#
# Everything below is the state of the tree the day this gate was added. It is a to-do list, not
# a policy. Remove a line by fixing the page, not by editing this file.

# --- fonts: FIXED, no longer baselined --------------------------------------
# The three Google Fonts @imports (web-twin, web-flasher, tools/docs_3d_page) were removed rather
# than baselined. Each page already named real fallbacks, so nothing was lost visually, and CSS
# has no integrity attribute — there was no verified form of that dependency to move to.
#
# --- the flasher: FIXED, no longer baselined --------------------------------
# web-flasher/index.html now pins esp-web-tools to the exact 10.4.0 with integrity= and
# crossorigin=, plus a CSP whose script-src names unpkg.com explicitly. Option (2), vendoring
# dist/web/ into the repo, is still the better end state: install-button.js dynamically imports
# two further chunks, and `import()` carries no integrity metadata, so those two remain covered by
# the CSP origin list alone. Recorded in security/README.md as a known blind spot, not here,
# because it is not a finding this gate can see.
